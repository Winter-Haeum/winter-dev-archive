# Winter Dev Archive Document Generation Policy

이 문서는 Winter Dev Archive의 모든 학습 문서에 공통 적용되는 기본 정책입니다.

이후 생성되는 모든 Step / Lesson 문서는 별도 요청이 없어도 아래 규칙을 자동 적용합니다.

---

## 작업 규칙

1. 원문 내용 절대 삭제 금지
2. 예제 코드, 주의사항, 강사 코멘트 모두 유지
3. 원문 순서 최대한 유지
4. Winter Dev Archive 문서 형식 적용
5. 부족한 내용은 초보자 기준으로 필요한 경우만 보충
6. markdownLoader.js frontmatter 규칙 준수
7. 최종 결과는 바로 저장 가능한 Markdown(.md) 형태
8. 원문 명령어, 코드, 스크립트는 수정하거나 축약하지 말 것
9. 원문에 없는 내용을 추가할 수 있으나 원문을 대체하거나 왜곡하지 말 것
10. 원문이 이미 충분한 경우 불필요한 재설명이나 재요약 금지
11. 원문에 포함된 표, URL, 이미지 설명도 유지
12. 본문 하단에 "다음 단계", "다음 문서" 안내는 작성하지 말 것
13. 단순 나열형 정보(UI 요소, 용어 정리, 비교 항목 등)는 가독성을 위해 표 형태로 재구성 가능
14. 표로 변경하더라도 원문 내용은 100% 포함
15. 실습형 문서는 인터랙티브 데모 영역 추가 가능
16. 체크포인트는 실제 체크 가능한 형태를 고려 (`- [ ]`)
17. 한국어 문서 가독성을 고려하여 단어가 어색하게 줄바꿈되지 않도록 구성

## 문서 구조

모든 문서는 가능한 동일한 구조를 사용한다.

아래 구조는 AI가 보충하는 섹션의 표준 형식이며, 원문에 이미 제목이 있는 섹션은 원문 제목을 그대로 유지한다.

```
# 제목

## 🎯 학습 목적

## 📖 개념 설명

## ⚙️ 동작 원리

## 💻 예제 코드

## ⚠️ 주의사항

## 📝 핵심 정리

## 🔗 참고 자료

## ✅ 체크포인트
```

원문에 없는 섹션은 필요 시 생략할 수 있다.

아래 표준 제목은 원문의 같은 의미 섹션에도 동일하게 적용하여 전체 문서 스타일을 통일한다.

| 원문에서 자주 쓰는 표현        | WDA 표준 제목     |
| ------------------------------ | ----------------- |
| 학습 목표, 이 수업에서 배울 것 | `## 🎯 학습 목적` |
| 개념 설명, 이론, 실습 개요     | `## 📖 개념 설명` |
| 동작 원리, 내부 구조           | `## ⚙️ 동작 원리` |
| 예제 코드, 코드 예시           | `## 💻 예제 코드` |
| 주의사항, 주의                 | `## ⚠️ 주의사항`  |
| 정리, 요약, 핵심               | `## 📝 핵심 정리` |
| 참고 자료, 링크                | `## 🔗 참고 자료` |

단, 원문에 고유한 섹션 제목이 있고 표준 제목으로 대체하면 문맥이 어색해지는 경우에는 원문 제목을 유지한다.

### JavaScript Basics 챕터 구조 (2-1 기준)

JavaScript Basics 챕터는 아래 구조를 사용한다. 위 표준 구조보다 이 구조를 우선 적용한다.

```
[frontmatter]
[<style> CSS 블록 — wda-callout/wda-goal/wda-fgrid/wda-summary-table 등]

## 🎯 학습 목표  ← wda-goal div로 작성

## 1. [섹션 제목]
## 2. [섹션 제목]
...
## N. 📋 최종 핵심 요약표  ← wda-summary-table
```

**콘텐츠 요소 선택 기준 (2-1 기준):**

| 콘텐츠 성격 | 사용 형식 |
| --- | --- |
| 비교 / 차이 설명 | 표(Table) |
| 여러 항목 묶음 (4대 장점 등) | 카드(wda-fgrid/wda-fcard) |
| 보충 설명 / 주의사항 / 팁 / 개념 | callout (색상 기준: 섹션 19) |
| 짧은 연결 설명 / 흐름 설명 | 일반 본문 |
| 예제 코드 | 코드블록 (언어: `js`) |
| 마지막 핵심 정리 | wda-summary-table |

원문 내용은 삭제하지 않고, 문장 의미와 코드 내용은 수정하지 않는다.

### 부록(Appendix) 문서 배치 규칙

부록 문서는 "단원 맨 마지막에 몰아넣는 보너스 자료"가 아니라 **관련 개념 바로 뒤에 붙는 중간 보충 자료**로 취급한다.

1. 부록 문서를 섹션(sectionDocs) 맨 아래로 자동 정렬하지 않는다.
2. 부록은 원본 학습 흐름에서 지정된 위치를 우선 유지한다.
3. 원본에서 부록이 특정 개념 다음에 위치한다면, `navigation.js`의 `sectionDocs` 배열에서도 같은 위치(해당 본문 문서 바로 다음 인덱스)에 배치한다.
4. 부록의 위치가 명확하지 않은 경우에는, 내용상 관련성이 가장 높은 본문 문서 바로 뒤에 배치한다.
5. 새 부록을 추가할 때 섹션의 다른 문서 순서는 변경하지 않고, 부록 항목만 올바른 위치에 삽입한다.

**예시 — JavaScript &gt; 4. ES6+ 심화 문법 (고정 순서):**

```
4-1 ES6 + 최신 문법 알아보기
4-2 화살표 함수, 구조분해, 스프레드
4-3 스코프 체인과 클로저 이해하기
부록: 생성자 함수의 모든 것   ← 4-3 직후 (this/생성자 개념 보충)
4-4 this 바인딩 파헤치기
```

**예시 — JavaScript &gt; 1. JavaScript 기본 문법:**

```
1-3 데이터 타입
1-4 연산자 알아보기
부록: 타입 변환과 단축 평가   ← 1-4 직후 (암묵적 변환은 연산자, 단축 평가는 논리 연산자 심화 개념)
1-5 조건문과 반복문으로 흐름 제어하기
```

## 문서 디자인 시스템

- Step과 Lesson은 동일한 UI와 섹션 스타일을 사용한다.
- 문서마다 제목 스타일이 달라지지 않도록 한다.
- 코드와 명령어만 코드 블록을 사용한다.
- 일반 설명문은 불필요하게 코드 블록으로 감싸지 않는다.
- 단, 원문이 일반 설명문을 코드 블록으로 표현한 경우 원문 형식을 유지한다.
- 현재 작성된 문서와 앞으로 생성될 문서 모두 동일한 스타일을 유지한다.

---

## 원문 보존 원칙

가장 중요한 원칙은 **원문 100% 보존**이다.

- 원문 내용을 삭제하지 않는다.
- 원문 제목을 임의 변경하지 않는다.
- 원문을 AI가 다시 자기 말로 요약하지 않는다.
- 디자인 개선은 가능하지만 원문을 대체하지 않는다.

원문 보존 원칙이 문서 구조 규칙보다 우선한다.

## 향후 작업 방식

이 문서는 Winter Dev Archive의 공식 문서 생성 정책이다.

앞으로는 아래 형식으로만 요청해도 이 정책을 자동 적용하여 문서를 생성한다.

```
저장 위치:
content/[카테고리]/[섹션]/[파일명].md

[원문 붙여넣기]
```

별도의 작업 규칙을 다시 입력하지 않아도 된다.

---

## 문서 표현 방식 원칙

Winter Dev Archive는 단순 원문 보관소가 아니라 **디지털 참고서 + 실습 교안**을 목표로 합니다.

AI는 원문 내용을 100% 유지하는 것을 전제로, 가독성과 학습 효과를 높이기 위해 자유롭게 레이아웃을 재구성할 수 있습니다.

18. 원문 내용(문장, 코드, 명령어, URL, 주의사항, 강사 코멘트)은 100% 유지한다.
19. 원문 내용을 삭제하거나 축약하지 않는 범위에서 가독성을 높이기 위한 UI 재구성을 허용한다.
20. 단순 나열형 정보는 상황에 따라 다음 형태로 변경할 수 있다.
    - 표(Table)
    - 카드(Card)
    - 단계형 카드(Step Card)
    - 타임라인(Timeline)
    - 비교 박스
    - 인터랙티브 데모
    - 체크리스트
    - 플로우 다이어그램
21. 문서 작성 중 사용된 단순 번호 체계(예: 2-1, 2-2, 3-1)는 반드시 유지할 필요는 없으며, 더 좋은 구조가 있다면 자유롭게 재구성할 수 있다.
22. 코드블록(text 박스)은 실제 코드, 명령어, 프롬프트, 복사해서 사용해야 하는 내용에 우선 사용한다. 일반 설명 문장은 가능한 한 일반 본문, 표, 카드 UI 등으로 표현한다.
23. AI는 원문을 단순 복사하는 것이 아니라, 학습자가 한눈에 이해할 수 있는 디지털 참고서 형태로 문서를 구성한다.
24. 기존에 등록된 모든 문서와 앞으로 생성되는 모든 문서에도 동일한 정책을 적용한다.
25. Winter Dev Archive는 단순 Markdown 문서가 아니라, **디지털 참고서 + 다이어리 스타일의 교안 웹**을 목표로 한다. 전체 문서가 한눈에 읽히고, 학습 흐름이 자연스럽게 이어져야 한다.
26. AI는 카드, 타임라인, 단계형 UI, Callout Box, 비교 카드, 완료 배너 등 다양한 시각화 컴포넌트를 적극 활용하여 문서를 구성할 수 있다.
27. 긴 설명문은 가능한 한 시각적으로 분절하여, 정보를 단번에 파악할 수 있도록 레이아웃을 구성한다.
28. **"읽고 싶은 교안"**을 최우선 기준으로 삼는다. 텍스트 나열보다 시각적 구조화가 학습 효과를 높인다.
29. 이 원칙은 신규 문서뿐만 아니라 기존에 등록된 모든 문서에 동일하게 적용한다.
30. 단순 번호 체계(1-1, 2-1, 3-1 등)는 학습 구조를 이해하는 데 꼭 필요하지 않다면, 시각적으로 더 읽기 좋은 카드·단계 번호(①②③)·타임라인 등으로 재구성할 수 있다.
31. AI는 단순히 안전한 변경만 하는 것이 아니라, Winter Dev Archive의 디자인 철학(디지털 참고서 + 다꾸 스타일 교안)에 더 적합한 방향을 우선 선택한다.
32. 단계형 설명이나 프로세스 설명은 가능하면 플로우 카드, 타임라인, 단계 카드 등을 우선 활용한다.
33. 원문의 "다음 단계", "다음 문서" 안내는 본문에서 제거할 수 있지만, "이론 학습 완료", "실습 완료" 같은 학습 완료 메시지는 반드시 유지한다.
34. 기존 문서를 포함한 전체 Winter Dev Archive에서 단순 내부 번호 체계(1-1, 1-2, 2-1 등)는 특별한 학습 구조상 필요하지 않다면 제거하고, 단계 카드·①②③ 번호·타임라인·플로우 카드 등 WDA 디자인 철학에 맞는 표현으로 통일한다. 문서마다 번호 표현 방식이 혼재되지 않도록 전체 일관성을 최우선으로 유지한다.
35. 단순 번호 체계(1-1, 1-2 등)를 제거하는 경우, AI는 학습 흐름이 끊기지 않도록 다음 중 하나 이상의 방식으로 하위 구조를 명확하게 표현한다: ①②③ 단계 번호 / STEP 카드 / 아이콘 + 섹션 제목 / 플로우 카드 / 타임라인. 번호를 제거한 자리를 단순 텍스트 제목만으로 남겨두지 않는다.
36. 단순 명령어(1~2줄)는 불필요하게 큰 코드블록으로 표현하지 않고, 인라인 코드 또는 소형 카드 형태를 우선 사용한다.
37. 설치 과정이나 절차형 설명은 가능하면 플로우 다이어그램, 단계 카드, 타임라인 등을 우선 활용한다.
38. 시각적으로 더 읽기 좋은 구조가 가능하다면 단순 텍스트 나열보다 다이어리형 정보 디자인을 우선 선택한다.
39. 플로우(절차)형 내용은 세로 배치로 고정하지 않는다. 가독성과 화면 공간을 고려하여 가로 플로우 카드, 세로 타임라인, 단계 카드 등 가장 적합한 레이아웃을 선택한다.
40. PC와 모바일 환경을 고려하여 가로 배치가 어려운 경우에는 자동으로 세로 배치가 가능한 구조(flex-wrap: wrap)를 우선한다.
41. 동일한 카드 레이아웃이나 정보 표현 방식이 한 문서 안에서 과도하게 반복되지 않도록 한다.
42. AI는 정보의 성격에 따라 카드, 메모 카드, 비교 카드, 표(Table), 플로우 다이어그램, 단계 카드, 타임라인, 색상 샘플, Callout, 완료 배너 등을 적절히 조합하여 시각적 리듬감을 만든다.
43. 같은 아이콘 카드 패턴이 연속으로 반복될 경우, 더 적합한 표현 방식이 있다면 다른 정보 디자인으로 변경할 수 있다.
44. Winter Dev Archive는 단순히 "잘 정리된 문서"가 아니라 "계속 읽고 싶고, 넘겨보고 싶은 디지털 참고서 + 다꾸 교안"을 목표로 한다. AI는 안전한 변환보다 더 읽기 좋은 정보 디자인을 우선 선택할 수 있다.
45. 같은 문서 안에서 카드 → 카드 → 카드처럼 동일한 패턴이 반복되지 않도록 하며, 필요하다면 카드 → 메모 → 비교표 → 플로우 → 타임라인 등으로 표현 방식을 적절히 변화시켜 읽는 흐름에 리듬감을 만든다.

## 콘텐츠 표현 원칙

1. 동일한 UI 컴포넌트(Table, Card, Callout, Code Block 등)를 목적 없이 과도하게 반복하지 않는다.
2. 같은 컴포넌트 유형이 2회 이상 연속으로 등장하지 않도록 한다. 연속 배치가 불가피할 경우 명확한 이유가 있어야 한다.
3. **학습 목표(학습 목적)는 비교 데이터가 아니므로 Table보다 Card 또는 Callout을 우선 사용한다.** 학습 목표는 독자가 문서를 펼쳤을 때 가장 먼저 읽는 영역이므로 시각적으로 명확하게 강조되어야 한다.
4. 콘텐츠의 성격에 맞는 UI를 선택하여 Visual Hierarchy(중요도 순서)와 Visual Rhythm(읽는 흐름의 리듬감)을 함께 유지한다.
5. "디자인 일관성"을 이유로 모든 섹션을 같은 형식으로 만들지 않는다. 가독성과 학습 효율이 항상 형식 일관성보다 우선한다.
6. 문서를 검토할 때 "연속된 표", "연속된 카드 박스", "연속된 Callout", "반복 패턴"이 있는지 확인하고, 시각적 단조로움이 느껴지면 변경을 검토한다.

## 기존 문서 리팩토링 정책

새로운 디자인 정책은 신규 문서뿐만 아니라 기존에 작성된 모든 문서에도 동일하게 적용된다.

- 모든 페이지를 순차적으로 검토하여 현행 정책에 맞지 않는 부분을 찾아 수정한다.
- 단순히 컴포넌트 종류를 교체하는 것이 아니라, 전체 흐름과 가독성을 고려한 리팩토링을 수행한다.
- 리팩토링 시 콘텐츠는 100% 보존하며, 삭제 또는 요약 축소 없이 표현 방식만 변경한다.
- 디자인 시스템은 지속적으로 발전하는 것으로, 일회성 작업이 아닌 반복 검토·개선 사이클을 따른다.

### 리팩토링 후 체크리스트

- □ Table 과다 사용 여부 (연속 3개 이상이면 재검토)
- □ Callout 과다 사용 여부 (연속 3개 이상이면 재검토)
- □ Card(fgrid) 과다 사용 여부 (연속 2세트 이상이면 재검토)
- □ 반복 레이아웃 여부 (동일 패턴의 섹션이 연달아 등장하는지)
- □ Visual Rhythm (읽는 흐름에 리듬감이 있는지)
- □ Visual Hierarchy (중요한 정보가 시각적으로 더 강조되는지)
- □ 학습 효율 및 가독성 (처음 보는 독자도 쉽게 읽을 수 있는지)

### 0. 최우선 원칙 — 가독성 절대 우선

> **"스티커를 붙인 예쁜 학습 노트"이지, "스티커 때문에 글씨가 가려지는 노트"가 아니다.**

이번 작업 목표는 "데코를 많이 붙이는 것"이 아니다.
**"실제 다꾸 노트처럼 자연스럽고 읽기 편한 교안"** 을 만드는 것이 목표다.

- 텍스트·제목·본문·표·코드블록·글머리표·버튼·링크를 절대 가리지 않는다.

- 공간이 부족하면 크기를 줄이거나 생략한다. 억지로 배치하지 않는다.

### 2. 캐릭터 크기 계층

박스 타입에 따라 캐릭터 크기를 계층화한다. left 배치는 항상 같은 섹션의 right보다 작게.

| 배치 위치                 | 크기 범위 | 대표값    |
| ------------------------- | --------- | --------- |
| wda-goal (right, 주인공)  | 178~192px | 182~188px |
| callout right (주요 배역) | 150~185px | 178~185px |
| callout left (보조 배역)  | 130~150px | 138~145px |
| wda-done                  | 130~180px | 142~152px |
| wda-steps (직접 배치 시)  | 130~180px | 130~168px |

**JavaScript Basics 챕터 캐릭터 배치 방식 (2-1 기준):**

JavaScript Basics 챕터에서는 캐릭터를 callout 박스 내부가 아닌, **섹션 제목 heading div 안에 overlay**로 배치한다.

- 크기: 126~138px (섹션당 1개, 문서 전체 2~3개)
- 배치 패턴: 제목을 `position:relative` div로 감싸고, 캐릭터를 `position:absolute` img로 넣음
- 위치: `right:0; top:-105px ~ -110px` (캐릭터 하단이 제목 위에 위치)
- 캐릭터 하단이 표 첫 줄이나 본문과 겹치지 않게 top 값 설정

```html
<!-- JavaScript Basics 캐릭터 배치 패턴 (2-1 기준) -->
<div style="position:relative;overflow:visible;margin:1.5rem 0 0.5rem;">
  <h2>N. 섹션 제목</h2>
  <img src="/images/character/캐릭터.webp" alt=""
       style="position:absolute;width:132px;right:0;top:-108px;opacity:.88;z-index:2;pointer-events:none;">
</div>
```

이 패턴은 추가 여백 없이 캐릭터가 오른쪽 빈 공간에 자연스럽게 올라간다.

**left 캐릭터 추가 규칙:**

- 권장 크기: 130~145px
- 최대: 150px (초과 시 QA 대상)
- 항상 같은 섹션의 right 캐릭터보다 작게

### 3. 캐릭터 위치 규칙 — left/right 번갈아

callout에서는 left ↔ right 교차가 기본 리듬이다.

- 연속 2회 동일 방향: 허용
- 연속 3회 이상 동일 방향: 금지

**박스 타입별 기본 방향:**

- 권장 크기: 130~145px / 최대: 150px

- 하단까지 내려오는 배치 금지

- 텍스트 시작선보다 안쪽 진입 금지
- 텍스트 박스 내부 침범 시 즉시 실패

```html
</div>
```

**허용 방식 2 — 비박스 height:0 div 사용 (v3.5 조건부 허용)**

박스 외부 여백, 섹션 구분선(---) 근처에 배치할 때 height:0 div 사용 허용:

```html
<div style="position:relative;height:0;overflow:visible;margin:0;">
  <img
    src="/images/decoration/마스킹 테이프 (N).webp"
    alt=""
    style="position:absolute;width:106px~120px;
              top:-6px ~ -10px; left:30%;
              z-index:1; pointer-events:none; opacity:.80;
              transform:rotate(-8deg ~ +8deg);"
  />
</div>
```

조건:

- 박스 라벨/텍스트 위 배치 금지
- 제목/소제목 바로 앞·뒤 배치 금지
- 구분선(---) 걸침 배치 시: 테이프 하단이 구분선에 **4~8px만 걸치도록** 배치

구분선 걸침 배치 시 top 값 기준:

- height:0 div가 박스 하단 margin 영역에 있을 때: `top: -6px ~ -10px` 권장
- top 값이 너무 크면(양수) 테이프가 다음 제목에 가까워지므로 주의

**배치 위치 허용/금지:**

| 위치                      | 허용 여부      | 조건                                   |
| ------------------------- | -------------- | -------------------------------------- |
| 박스 right 상단           | ✅ 허용        | 항상 허용                              |
| 박스 center 상단          | ✅ 허용        | 항상 허용                              |
| 박스 left 상단            | ⚠️ 조건부      | 라벨이 없는 박스만 허용                |
| height:0 div (비박스)     | ✅ 조건부 허용 | v3.5 추가 — 제목/라벨/텍스트 근처 금지 |
| wda-clabel 바로 위        | ❌ 금지        | 항상 금지                              |
| wda-goal-label 바로 위    | ❌ 금지        | 항상 금지                              |
| 박스 내부 첫 줄 텍스트 위 | ❌ 금지        | 항상 금지                              |

- left, center, right를 골고루 사용
- 동일 위치(예: right만) 반복 금지

**마스킹 테이프 안전거리 규칙:**

마스킹 테이프 하단 ↔ 라벨(wda-clabel / wda-goal-label / wda-memo-label) 상단 사이 거리:

| 판정 | 거리      |

| 실패 | 12px 미만 |

- 실제 겹치지 않아도 12px 미만이면 실패 판정
- 조정 방법: top 값을 음수 방향으로 올리거나 padding-top을 늘려 라벨을 아래로 내리기

**마스킹 테이프 공통 규칙:**

### 6. 소형 데코 배치 규칙 ★

**소형 데코 크기 계층 (v3.5 개정 — S/M/L/XL 4단계):**

| 계층 | 크기 범위 | 용도                             |
| ---- | --------- | -------------------------------- |
| S    | 33~42px   | 기본 포인트 장식                 |
| M    | 43~55px   | 주요 데코; 섹션 경계             |
| L    | 56~72px   | 강조 포인트; 섹션당 1~2개        |
| XL   | 73~100px  | 강조 포인트용; 문서 전체 1~2개만 |

**크기 혼합 규칙:**

- 색이 연한 데코는 M 이상 크기 적용
- S만 반복 금지 — 단조로움 방지
- 모든 데코가 비슷한 크기로 보이지 않게 함
- XL은 포인트용으로만 사용; 크기 차이가 화면에서 분명하게 보여야 함
- 크기 혼합: S + M + L 조합 권장, 연속 동일 크기 반복 지양

**Zone A — 섹션 경계 (height:0 div, 단독 1개 배치)**

- 별/반짝이/꽃/하트 등
- width: M(43~55px) 이상 권장
- 구분선 위에는 **최대 1개만** 배치 (6-B 한 줄 배치 금지 규칙 적용)
- top: -8px ~ -14px (크기가 클수록 더 올릴 것)
- 제목 150px 이내 배치 금지 (8-A 예외 조건 참조)

**Zone B — callout·memo 내부 소형 아이콘 (선택)**

- 핀/체크/스탬프/하트 아이콘 1개
- width: M~L(43~72px) 권장
- padding-right 또는 padding-left 여분 확보 필수
- 라벨 인라인 flex 방식 배치 허용 (본문 텍스트 겹침 방지)

**에셋별 크기 제한 규칙 (v3.5 추가):**

| 에셋 종류     | 허용 크기     | 금지        | 비고                                               |
| ------------- | ------------- | ----------- | -------------------------------------------------- |
| 별 아이콘     | L(56~72px) / XL(73~100px) | S·M 금지 | 화면 포인트 장식이므로 눈에 띄어야 함 |
| 느낌표 아이콘 | M(43~55px) 기준 | XL 과용 금지 | 강조력이 강하므로 M으로 절제              |

> **별 아이콘 계열 데코는 S/M 크기로 사용하지 않는다. 별 아이콘은 화면에서 포인트가 되어야 하므로 L 또는 XL 크기로만 사용한다. 공간이 부족하면 크기를 줄이지 말고 위치를 이동하거나 사용하지 않는다.**

> **느낌표 아이콘 계열 데코는 M 크기(43~55px)를 기본으로 사용한다. 느낌표는 강조력이 강하므로 XL 크기로 과하게 키우지 않는다.**

### 6-A. 소형 데코 텍스트 보호구역 ★

> **소형 데코도 텍스트를 가려선 안 된다.** 제목뿐 아니라 본문 문장·목록·코드블록·표 영역도 침범 금지.

**규칙:**

- 소형 데코는 텍스트 bounding box 기준 **최소 20~30px 거리** 확보 필수
- 글자 위에 걸치는 배치 절대 금지
- 텍스트 근처보다 **빈 여백 우선** 사용
- 위반 발견 시 처리 순서:
  1. **이동** — 빈 여백으로 이동
  2. **크기 축소** — 더 작게 만들어 회피
  3. **방향 변경** — top/left/right 조정으로 회피
  4. **제거** — 위 세 가지 모두 불가 시 최후 수단

---

### 6-B. 한 줄 연속 배치 금지 ★

> **절대로 한 줄에 데코를 연속 배치하지 않는다.**

**금지 예시:**

- 같은 구분선 위에 데코 2개 이상 배치
- 같은 height:0 div 안에 데코 2개 이상 배치
- 데코끼리 y축 차이가 40px 이하인데 좌우로 나란히 퍼져 있는 배치
- 왼쪽 1개 + 오른쪽 1개 형태로 같은 줄에 보이는 배치
- 왼쪽 + 중앙 + 오른쪽 형태로 같은 줄에 보이는 배치

**현재 한 줄에 연속 배치된 데코 해소 방식:**

- 삭제 금지 — 위치 이동으로 해소
- 같은 줄에 있는 데코 중 하나만 그 줄에 남김
- 나머지 데코는 위/아래로 이동
- 이동한 데코는 최소 60px 이상 y축 차이 확보
- 구분선 위에는 데코 **최대 1개만** 배치

### 6-C. 데코 배치 기본 방식 — absolute overlay ★

> **장식 데코는 레이아웃 흐름에 포함하지 않는다. 실제 스티커를 위에 붙인 것처럼 띄워 배치한다.**

**핵심 원칙:**

- 데코는 레이아웃 공간을 차지하지 않아야 함
- 제목 줄 높이, 박스 높이, 본문 위치, 카드 간격을 밀어내면 안 됨
- 제목 옆, 박스 모서리, 섹션 경계, 카드 주변, 캐릭터 주변 모두 absolute overlay 방식 우선
- 데코가 박스 밖으로 살짝 넘어가는 것은 허용
- 단, 텍스트·제목·본문·코드블록을 가리면 안 됨
- 데코가 잘릴 경우 부모 요소 또는 wrapper의 `overflow`를 `visible`로 조정

**배치 방식:**

| 위치 | 방식 |
|------|------|
| 제목 옆 | `height:0;overflow:visible` div + `position:absolute` (8-A 패턴) |
| 박스 모서리/내부 | 박스에 `position:relative` + 자식에 `position:absolute` |
| 섹션 경계 | `height:0;overflow:visible` div 단독 1개 배치 (Zone A) |
| 카드 주변 | 카드 wrapper에 `position:relative` + `position:absolute` |

**❌ 금지 방식:**

- 데코 때문에 제목/본문/박스/카드 위치가 밀리는 구조
- 데코 때문에 불필요한 `padding`, `margin`, spacer, 빈 `div`를 추가하는 방식
- 데코를 넣기 위해 박스 높이를 강제로 키우는 방식
- 단순 장식 목적의 스티커·데코 이미지(`.webp` 에셋)를 inline으로 삽입

**예외 — inline 사용 허용 사례:**

- 리스트 앞의 아이콘 (예: 📌 ✅ 📎)
- 문장 안의 이모지
- 코드 설명용 아이콘
- 단, 스티커/데코 이미지(`.webp` 에셋)는 위 예외에서도 inline 삽입 금지

### 8. 제목/소제목 보호구역 ★

> **제목과 소제목은 원칙적으로 장식 금지 구역이다.**

제목(`##`) 및 소제목(`###`) 기준 **8방향 모두 150px 이내** 데코 배치 금지.

```
     위
좌상  ↑  우상
← 왼쪽 [제목] 오른쪽 →
좌하  ↓  우하
     아래
```

**제목 직전/직후 height:0 div 배치 금지:**

```html
<!-- ❌ 금지 패턴 1 — 제목 직전 -->
<div style="height:0; overflow:visible;">
  <img ... />
</div>
## 제목

<!-- ❌ 금지 패턴 2 — 제목 직후 -->
## 제목
<div style="height:0; overflow:visible;">
  <img ... />
</div>
```

- 위반 시 즉시 실패 판정
- 이동 우선, 이동 불가 시에만 제거

### 8-A. 제목/소제목 옆 인라인 데코 예외 허용 ★

> 제목 오른쪽 끝에 붙는 인라인 장식은 허용한다.

**허용 조건:**

- 제목 글씨와 데코 사이 간격 **20~32px** 확보
- 제목과 같은 줄에 배치 (flex 또는 inline 방식)
- 제목 텍스트를 덮지 않음
- 제목 아래 본문 쪽으로 내려오지 않음
- 포인트 장식처럼 자연스럽게 보일 것

**금지:**

- 제목 위에 겹침
- 제목 아래 빈 공간에 애매하게 떠 있음
- 제목과 50px 이상 멀어져 연결감이 사라짐
- 구분선 위에 무관하게 배치

**구현 방식 — flex 컨테이너 (권장):**

```html
<div
  style="display:flex;align-items:center;gap:24px;margin-top:1.5rem;margin-bottom:0.75rem;"
>
  <h2 style="margin:0;">섹션 제목</h2>
  <img
    src="/images/decoration/꽃 아이콘 (N).webp"
    alt=""
    style="width:64px;opacity:.65;transform:rotate(-8deg);pointer-events:none;flex-shrink:0;"
  />
</div>
```

**라벨 인라인 배치 (wda-memo-label 등):**

```html
<div style="display:flex;align-items:center;gap:24px;margin-bottom:8px;">
  <span class="wda-memo-label" style="margin-bottom:0;">라벨 텍스트</span>
  <img
    src="/images/decoration/핀 아이콘 (N).webp"
    alt=""
    style="width:50px;opacity:.62;transform:rotate(-6deg);pointer-events:none;flex-shrink:0;"
  />
</div>
```

---

**⚠️ 제목 옆 데코·캐릭터 배치 방식 — v3.5 필수 규칙 (absolute overlay):**

> **제목/소제목 오른쪽 데코는 텍스트 흐름에 포함하지 않는다. 제목 뒤에 img를 inline-block으로 직접 붙이는 방식은 금지한다. 데코는 absolute overlay 방식으로 띄워 배치하며, 제목 줄 높이·margin·padding·본문 위치에 영향을 주면 안 된다. 데코가 위쪽 구분선을 살짝 넘어가는 것은 허용하되, 제목 글씨와 본문을 가리면 안 된다.**

**❌ 금지 방식 — inline 직접 삽입:**

```html
### 제목<img src="..." style="display:inline-block;">
```

금지 사유:
- 제목 줄 높이가 커짐
- 제목 영역이 데코 크기만큼 넓어짐
- 제목 위아래 여백이 비정상적으로 늘어남
- 본문 위치가 밀림

**✅ 허용 방식 A — height:0 absolute overlay (소형 데코 전용):**

```html
### 6. Claude Code 자동 설정 프롬프트

<div style="position:relative;height:0;overflow:visible;margin:0;padding:0;">
  <img src="/images/decoration/책갈피 아이콘 (5).webp" alt=""
       style="position:absolute;top:-70px;left:36%;width:50px;transform:rotate(-10deg);pointer-events:none;z-index:2;opacity:.78;">
</div>
```

핵심 기준:
- `height:0;overflow:visible;margin:0;padding:0` — 레이아웃 공간 0 차지
- `top` 값은 음수 충분히 설정 — 제목 글씨 위쪽으로 올라가야 함 (권장: `top:-60px ~ -80px`)
- 제목 위 여백은 다른 섹션과 동일하게 유지됨
- 제목 글씨·본문과 겹치면 실패
- 데코가 위쪽 구분선을 살짝 넘어가는 것은 허용

**✅ 허용 방식 B — position:relative heading div (JavaScript Basics 기준 패턴):**

제목(`h2`)을 `position:relative` div로 감싸고 데코·캐릭터를 그 안에 `position:absolute`로 배치한다. JavaScript Basics 챕터의 기본 패턴이다.

```html
<div style="position:relative;overflow:visible;margin:1.5rem 0 0.5rem;">
  <h2>N. 섹션 제목</h2>
  <img src="/images/decoration/꽃 아이콘 (7).webp" alt=""
       style="position:absolute;width:54px;top:-12px;right:8px;z-index:2;pointer-events:none;opacity:.74;transform:rotate(10deg);">
</div>
```

핵심 기준:
- wrapper div의 `margin:1.5rem 0 0.5rem`이 일반 h2의 margin을 대체 — 추가 여백 없음
- 데코·캐릭터가 div 밖으로 나가도 `overflow:visible`로 보임
- 제목 텍스트와 본문을 가리면 안 됨
- 동일 div 안에 데코 1개 + 캐릭터 1개까지 허용 (서로 다른 위치에 배치)

### 8-B. 데코 위치 패턴 다양화 ★

데코는 단순 픽셀 이동이 아니라 배치 패턴 자체를 다양화한다.

**사용 가능한 배치 패턴:**

- 단독 배치
- 좌측 클러스터
- 우측 클러스터
- 중앙 포인트 배치
- 지그재그 배치
- 대각선 흐름 배치
- 이미지/캐릭터 주변 배치
- 박스 모서리 배치
- 제목/소제목 끝에 간격 두고 인라인 배치 (v3.5 추가)

**규칙:**

- 동일한 배치 패턴이 연속 반복되지 않게 한다
- 데코를 애매한 빈 공간에 아무렇게나 배치하지 말고 제목/박스/이미지/캐릭터와 시각적으로 연결되어 보이게 배치한다
- 구분선 위에만 몰아넣지 말고 페이지 전체에 분산 배치한다

**각도 기준:**

- 일반 데코: -12deg ~ +12deg 범위에서 자연스럽게 회전
- 마스킹 테이프: -8deg ~ +8deg
- 너무 모든 데코가 정자세로 보이지 않게 할 것

### 8-C. 데코 에셋 다양화 규칙 ★

> 여러 챕터에서 같은 데코가 반복 사용되는 느낌이 강하지 않게 한다.

- 항상 같은 하트·구름/무지개·꽃·반짝이·마스킹테이프만 반복 사용 금지
- `/images/decoration/` 폴더 안의 다양한 에셋을 골고루 활용
- 소품, 스탬프, 책갈피, 잎사귀, 느낌표, 핀, 말풍선, 종이클립 등 적극 활용
- 폴더 전체 목록 출력 금지 — 사용한 새 에셋 이름만 보고
- 새 이미지 생성 금지
- 기존 프로젝트 에셋만 사용, 외부 이미지 추가 금지

**반복 사용 방지 규칙:**

- 하트, 꽃, 반짝이, 구름/무지개, 마스킹테이프만 반복 사용하지 않는다.
- 같은 종류의 데코 절대 사용 금지한다.
- 최근 챕터에서 자주 사용한 에셋은 다음 챕터에서 우선순위를 낮춘다.
- 소품 아이콘, 느낌표 아이콘, 책갈피, 잎사귀, 종이 클립, 말풍선, 스탬프를 우선 검토 대상에 포함한다.
- 데코를 선택할 때는 익숙한 에셋보다 현재 챕터의 주제와 연결되는 에셋을 우선한다.

**우선 사용 권장 카테고리:**

데코가 반복적으로 비슷해 보일 경우, 다음 카테고리를 우선 검토합니다.

- 소품 아이콘
- 느낌표 아이콘
- 책갈피 아이콘
- 잎사귀 아이콘
- 종이 클립 아이콘
- 말풍선 아이콘
- 스탬프 아이콘
- 체크 아이콘
- 핀 아이콘

**에셋별 크기 제한 (v3.5 추가):**

에셋 종류에 따라 크기 범위가 고정된다.

- **별 아이콘**: L(56~72px) 또는 XL(73~100px)만 허용. S·M 사용 금지. 포인트 장식으로 눈에 띄어야 하며, 공간 부족 시 크기를 줄이지 말고 위치를 이동하거나 제거한다.
- **느낌표 아이콘**: M(43~55px)을 기준 크기로 사용. 강조력이 강한 에셋이므로 XL로 과하게 키우지 않는다.

**gap 확보 순서:**

**권장 패턴:**

```
[상단] wda-goal: RIGHT 큰 캐릭터 (178~192px)
  ↓  height:0 div: 단독 데코 M~L (섹션 전환 쉼표)
  ↓  callout: LEFT 작은 캐릭터 (130~150px)
  ↓  callout: RIGHT 큰 캐릭터 (150~185px)
  ↓  height:0 div: 단독 데코 M~L
  ↓  callout: LEFT 작은 캐릭터
  ↓  wda-steps: 마스킹 테이프 또는 캐릭터
  ↓  height:0 div: 단독 데코 L~XL
[하단] wda-done: 마무리 캐릭터
```

**크기 리듬 금지 패턴:**

- 큰(178px+) → 큰(178px+) → 큰(178px+) 연속 배치 금지
- 동일 방향 연속 3회 이상 금지

**권장 크기 리듬:**

- 큰(RIGHT) → 작은(LEFT) → 큰(RIGHT) → 작은(LEFT)
- 또는 큰 → 데코만 있는 섹션 → 작은 → 큰

### 11. 제거보다 이동 우선 원칙 ★

문제 발견 시 처리 순서:

1. **이동** — 다른 위치로 이동 가능한지 확인
2. **크기 조정** — 더 작게 만들어서 해결 가능한지 확인
3. **방향 변경** — left↔right 방향 전환으로 해결 가능한지 확인
4. **제거** — 위 세 가지 모두 불가능할 경우만 제거

> **삭제는 최후 수단이다.** 기존 데코를 과하게 삭제하지 않는다.

### 19. 보조 설명 박스 / callout 스타일 통일 규칙

#### 19-1. 역할별 색상 통일

| 역할 | 클래스 | 색상 | 사용 기준 |
|---|---|---|---|
| 보충 설명 / 배경 설명 | `wda-ci` | 보라색 | 개념을 보충하거나 맥락을 추가할 때 |
| 주의사항 / 경고 | `wda-cw` | 주황색 | 실수하기 쉬운 내용, 위험 요소 경고 |
| 개념 정의 / 기본 개념 | `wda-cy` | 연노랑색 | 핵심 개념을 간결하게 정의할 때 |
| 팁 / 권장 / 실무 팁 | `wda-cs` | 초록색 | 권장 방식, 실무 팁, 사용 팁 |

#### 19-2. 라벨 위치 규칙

- `보충 설명`, `주의사항`, `실습 포인트`, `핵심 요약` 등의 라벨은 **박스 바로 위 단독 단락**으로 배치한다.
- 형식: `**보충 설명**` (bold, 이모지는 선택). JavaScript 챕터는 이모지 없이 `**보충 설명**` 형태를 기본으로 사용한다.
- 박스 안 `wda-clabel`은 역할을 구체적으로 나타내는 짧은 이름을 사용한다.
  - 예: `🔹 배치 원칙`, `⚠️ 주의사항`, `💡 사용 팁`, `개념`
- 박스 밖 라벨과 박스 안 `wda-clabel`이 동일 텍스트로 반복되지 않도록 한다.
- 박스 안에는 라벨 없이 실제 설명 내용만 남긴다.

#### 19-3. Bullet 줄바꿈 필수

- callout 내부 bullet 항목은 각 항목마다 `<br>` 태그로 줄바꿈을 명시한다.
- VitePress는 HTML 블록 내부에서 Markdown 줄바꿈을 처리하지 않으므로 `<br>`이 필수다.

#### 19-4. 박스 여백 규칙

- callout의 기본 margin은 CSS에 정의된 대로 유지한다 (`.wda-callout` 기준 `.8rem 0 1.4rem`).
- 데코와 callout이 겹칠 경우 `padding-right` 또는 `padding-left`로 내부 여백을 조정한다.
- 데코 때문에 문서 외부 여백(margin)을 늘려서는 안 된다.

#### 19-5. 색상 오용 방지

- 팁/권장 내용에 `wda-cw`(주황/경고색)을 사용하지 않는다.
- 개념 정의에 `wda-ci`(보라/보충색)을 사용하지 않는다 — `wda-cy`를 사용한다.
- 보충 설명 역할에 `wda-cs`(초록/팁색)을 사용하지 않는다.

#### 19-6. 데코와 callout 충돌 방지

- callout에 데코를 overlay할 경우 반드시 `overflow:visible`과 `position:relative`를 callout div에 추가한다.
- 데코가 callout 바깥으로 튀어나오더라도 레이아웃 흐름에 영향을 주지 않도록 `height:0;overflow:visible` 패턴을 사용한다.
- 데코가 텍스트, 복사 버튼, 표를 가리면 안 된다.

#### 19-7. 적용 대상

- 이 규칙은 모든 WDA 문서의 `.wda-callout` 블록에 적용한다.
- 신규 문서 작성 시 처음부터 이 규칙을 따른다.
- 기존 문서 수정 시 수정 범위 내의 callout을 이 규칙에 맞게 정리한다.
